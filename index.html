How many tokens does your plan buy?

:

Credits are priced at face value: the plans’ ×3 credit ratio is inherent in the credits (Pro $20 paid → $60 credits, Max $100 → $300 credits), so the rows need no paid-dollar division. The plans’ credits are a monthly grant, so every figure below is a monthly token budget. Each column is an in : out token split from measured runs — real interactive agent sessions (OpenCode, Claude Code logs) sit at 40:1–190:1 raw tokens (60:1 is the conservative pick) — and the custom column prices whatever split you type in the fields above. Real sessions also run ~90% of input as cache reads at a ~0.1x rate, cost-weighting them to ~3:1–6:1: that discount is what the S(x) slider above models — a measured S keeps precedence, and models without a published cached-input discount sit at S(x) ≡ S0. Each cell is the input, output and total tokens the plan’s credits buy at that split. This is a presentation-layer estimate: nothing persisted changes.

Verdicts compare what the same monthly budget buys on each system. The new plan sells credits at a per-tier multiplier over money paid ( at this doc's tier: Max $100 → $300 credits), so a new-side figure of $X in credits really costs $X ÷  paid. The margin is stated in paid dollars. Example: a task that burns $.00 of new-plan credits costs $1.00 paid.

The two price columns are nominal dollars for the token scenario set in the «tokens in» / «tokens out» inputs, 1M in / 250k out by default. The new column prices the scenario exactly on the official table, where input, cached input and output each carry their own rate, and follows the S(x) slider. The legacy meter emits a single pp read per bracket with no in/out decomposition because the GPU-time rate was never published, so the legacy column applies the cell's measured pp/1M to the scenario's in+out total. Hover for the underlying meter read and the per-task prices. A sub-tick weekly read falls back to the session-derived equivalent, marked «session».

The verdict chips compare each cell's measured per-task prices, the measured legacy read against the new plan priced live at the cell's own measured token mix and the slider's S(x), so they follow the slider for assumed-S models and never the scenario inputs. The meter-native view lives in the threshold chart below. Every verdict shows its margin, the chip's +X %: how much more expensive the loser is, (loser − winner) ÷ winner. It can exceed 100 % when the loser costs more than twice the winner. A verdict exists only when the margin clears the tie band, >2 meter ticks or >5 % of the cheaper cost. Inside it the cell is a tie.

Legacy quota vs billed tokens

computed from the raw runs/*.jsonl + batches/*.jsonl lines alone (k=1 cells are the derivatives' baseline; k>1 cells and the calibration/probe workstreams stay out of the cells). The threshold pp/1M prices each cell's OWN measured token mix on the table: an unmeasured cell reports no data and never borrows a threshold. Verdicts, margins and the threshold compare PAID dollars: the new plan sells credits at a per-tier multiplier, so its nominal credit cost divides by credit_ratio=3 (the anchor's Max tier: $100 -> $300 credits); the per-task cost figures stay at face value. A verdict is {winner, margin_pct}, the margin (loser - winner)/winner: a real margin is >2 meter ticks or >5 % of the cheaper cost; a sub-tick winner (weekly reads 0.0) prices with its session-derived weekly-equivalent, falling back to the loser's own cost (exactly 100 %) with no session reading either; the per-rep quantiles carry the full uncertainty. Both windows ship per bracket: weekly is the primary (the anchor); session figures are the derived secondary signal, unanchored and never an independent anchor: session $/pp = weekly $/pp / R (R = session:weekly ticks, live verification 6.22, expected range 5-7); the weekly window remains the study's unit of account and its only anchor. Pooled brackets (workload null) are never cells: their per-workload legacy is allocated in 'pooled' as token shares, marked allocated and never verdicted; who-wins counts only measured verdicts.
